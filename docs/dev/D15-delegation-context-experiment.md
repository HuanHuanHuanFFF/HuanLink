## 验收边界

实现默认关闭的本地单用户实验：按任务压缩会话、维护带版本的上下文、判断新消息是否需要同步、把用户证据和授权分析随 A2A 派单发送；远端具体权限请求独立复核，明确已有授权优先自动处理，有歧义才询问用户。

推荐选择：复用 MainAgent 的模型配置；压缩与权限复核均无 Tool；原始事实保留，引用由程序提取并校验；使用有限预算和版本化快照，记录远端接收回执；限制变化优先处理。Codex 的项目、工作区、执行模型和沙箱仍由 Adapter 管理。语义分析不能扩大 Adapter 的硬上限。

公开验收接缝：Core 上下文/权限协调合同，OpenAI Agents 结构化模型输入输出，A2A HTTP 任务包与控制消息，Adapter 到受控 app-server 的真实协议进程。重点覆盖证据伪造、授权过时、无关同步、重复/乱序/丢回执、跨任务审批、超时取消和恢复原操作。

## 批次

- B01：任务上下文压缩、证据校验、版本与同步判断，保存实验状态。
- B02：A2A 传递和远端上下文消费、更新回执；保持现有项目派单及生命周期兼容。
- B03：权限请求、独立复核与自然语言确认回流；批准绑定原请求、有效期和单次消费。
- B04：正式组合根的显式实验开关、受控闭环验证、两路独立只读压力审查和结果记录。

## 边界与验证诚实性

不建设多租户权限平台，不恢复旧自建 AgentLoop/PolicyEngine，不将实验默认启用到用户运行服务。不承诺检测同一沙箱内的全部任务语义越界，也不承诺撤回已发生的副作用。新能力不能自动继承 D14 的提交权限。

自动化协议验证与真实模型/QQ/真实 Codex 任务分别记录。模型语义正确率、漏同步率和用户询问频率需实际样本验证，不由字段映射测试替代。版本回执说明远端接收上下文，不等于模型已经理解或完成执行。

## 已实现的实验行为

- 委派时使用独立、无 Tool 的结构化模型调用。程序提供可引用的 owner 消息 ID；返回摘要、进展、决定、限制、未决问题和授权分析，原话由会话记录提取。非 owner、不存在或越界引用使构建失败。
- 维护每个委派的不可变版本、已处理事实游标和远端接收版本，SQLite v4 保存快照。无关变化推进本地游标而不重发远端摘要；相关变化发同一活动 turn 的补充输入。识别到取消、授权缩小或新增禁令时停止原任务，不宣称撤回已完成操作。
- 任务包是用户侧数据，Codex 配置仍在 Adapter。实验线程以 `read-only + on-request` 启动。支持原生 command/file-change 单次审批；不签发 session-wide grant，不采纳命令规则扩大建议，未知补丁和 root grant 拒绝。
- 独立 Reviewer 根据用户原话、当前任务和原生待执行操作决定 approve/deny/ask-user。模型给出的授权范围仍是分析；初始沙箱与可支持的审批类别由程序决定。一次批准可能让该具体命令产生沙箱外效果，工作目录不构成该命令的完整资源隔离边界。
- `requestedAtRevision` 记录原生操作提出请求时的上下文。用户后来确认可以产生更新版本；必须用更新后的原话重新复核，并以 Adapter 当前已接收版本消费同一个 approvalId，不能更换原操作。
- 已问过的请求必须有提问之后的新 owner 证据才能转为批准。同会话多请求须有唯一 taskId/approvalId 或消息回复引用；正文与引用冲突保持等待。重复决定只返回原回执，过期、取消或失配请求明确拒绝。
- 普通 requestUserInput 仍使用原问题 ID 续接同一 Task/turn；同步回执保留 questions。普通问题与权限请求异常并发时停止执行端，避免两种暂停状态互相覆盖。

## 启用与验证入口

功能默认关闭，本轮没有修改用户现有运行配置或重启服务。仅在独立测试项目中启用两侧开关，并先核对 Adapter 注册项目的工作区与分支。

实验使用独立工作区自己的 `.huanlink/data`。本分支会迁移数据库至 SQLite schema v4；旧分支不能读取新版本，不把实验数据库复用于原服务。

在 `.huanlink/config/server/orchestration.json` 现有对象中增加：

```json
{
  "delegationExperiment": {
    "enabled": true,
    "authorizedSenderIds": ["实际授权用户的平台ID"],
    "maxInputChars": 48000,
    "maxContextChars": 16000
  }
}
```

在 `.huanlink/config/adapters/codex/runtime.json` 增加 `"experimentalDelegation": true`。配置变更需重启对应实验服务。禁用任一侧不能得到完整实验闭环；关闭 Adapter 时拒绝携带实验任务包的派单。

默认预算按字符计算，不冒充精确 token 计数。每次输入最多 48000 字符、任务包最多 16000 字符，最多处理 16 个批次。超限、证据无效或同步结果不明明确报错；结果不明不自动重发，也不继续批准权限。模型调用默认 30 秒期限。

可复现入口：

- `corepack pnpm test`：默认自动化回归，不调用真实模型。
- `corepack pnpm --filter @huanlink/server test tests/delegation-runtime.test.ts`：MainAgent 工具、真实 A2A HTTP、临时 Git 工作区、真实脚本 stdio 进程；专业模型与判断模型均受控。
- `corepack pnpm --filter @huanlink/server test:real:deepseek tests/real/delegation.real.ts`：独立、显式的真实模型合成测试，需在进程环境提供现有配置指定的密钥。只发送合成对话，不执行代码任务；没有密钥时跳过。测试前按根脚本构建全部依赖，避免使用陈旧 dist。

## 审查驱动修正

两路独立只读压力审查和受控闭环共同确认并修复：

1. SDK 在 input-required 后结束原状态消费者；新增的带外权限恢复需继续保存后续状态，否则真正执行完成也不能回流。使用 SDK 公开 ResultManager/事件接口接续持久化。
2. 已关闭或失配的原生权限请求必须收到明确拒绝，不能仅从本地集合删除；拒绝写入失败关闭运行时并拒绝新执行。
3. 多任务的裸确认、正文与 replyTo 指向冲突不能分别变成多个授权；原始证据、首次提问游标和唯一目标共同约束绑定。
4. 普通问题待答期间的上下文同步不能清空 questions 或阻断原 Task continuation；两种原生暂停不能并存覆盖。

## 真实模型小样本（2026-09-30）

现有 `deepseek-v4-flash` 配置的一轮四检查点通过：保留 owner 证据、拒绝明示禁止的 push、允许明示授权的 npm test、识别 owner 取消。四次调用约 5.2、1.3、1.4、15.7 秒；只是当次观测，不是性能分布。

早期合成输入中的非 owner 消息被模型选择为 retainedMessageIds，程序拒绝了这份任务包。补充明确可选证据 ID 列表与字段规则后，上述检查通过。保留这个失败作为限制：结构化输出成功不代表引用合法，合法引用也不证明授权语义判断一定正确。

尚未验证真实 QQ→真实 Codex 编码/文件写入/原生权限执行的完整链路；普通待答时 turn/steer 的新组合目前只有官方协议与受控进程证据。没有大样本误放行率、漏同步率、长对话压缩质量或打扰频率结论。SQLite 重开保留事实和快照，不自动恢复远端任务或待审批原生 RPC。实验处理委派侧上下文，不替代 MainAgent 自身的全局 token 窗口压缩。
