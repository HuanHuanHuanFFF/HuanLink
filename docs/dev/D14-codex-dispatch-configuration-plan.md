# D14：Codex Adapter 项目与派单配置

> 状态：已确认，开发中（2026-09-30）。属于 `dev/v1.0-runtime-integration`；按可验证批次 commit，文档与代码分开提交，全部完成后统一 push，并由该分支创建一个 PR。不自动合并。

## 目标与确认边界

- 正式 Adapter 读取 `.huanlink/config/config.json` 显式引用的 runtime/project JSON，不再以遗留环境变量或硬编码分支选择执行目标。
- 派单必填稳定 `projectId`；`modelId`、`reasoningEffort` 可覆盖项目默认值。默认强度使用项目配置，仓库示例为 `high`；非法项目或模型/强度组合不启动 Codex 执行，不静默降级。
- 项目配置持有固定工作区和预期分支。工作区支持本机绝对路径或相对于 HuanLink 项目根的规范路径；模型不能传任意目录或分支。只验证，不创建 worktree、不切分支、不丢弃已有修改。
- 同一规范工作区同时最多一个活动 Task，忙时拒绝，不增加等待队列；不同工作区可并行。占位跨不同 Session 生效，`input-required` 仍占位到任务终态。
- 项目间 Codex 会话隔离；同一任务的追问保持原项目、模型和强度，不借 continuation 改配置。独立任务可重新覆盖执行参数。
- Core 只携带协议无关的结构化输入；Codex 参数校验、路径解析、分支保护、能力校验与会话隔离归 Adapter。A2A 集成负责结构化 Part 编解码，保留原派发未知/不自动重试语义。

## 分批实施

1. 配置与协议基础：项目默认强度、固定目录解析、Codex 模型能力列表和逐 turn 显式参数；公开测试先红后绿。
2. 派单闭环：Tool → Core → A2A → Adapter 结构化参数、项目会话隔离、工作区占位与续接冻结；正式 JSON 入口和配置 README。
3. 验收与审查：受影响包回归、类型/构建/格式检查、受控协议进程组合测试；两名独立只读压力 Reviewer，修复确认问题并复查后提交结果文档。

## 用户已确认的验收接缝

- 配置加载：默认值、合法/非法路径与分支、重复项目和实际工作区校验。
- MainAgent → A2A：必填项目、可选覆盖参数、准确结构化传递、来源去重、缺失/非法字段和现有 Task 生命周期不回退。
- Adapter → Codex：从 `model/list` 校验实际支持的模型和强度；不同项目 thread 不混用；同目录竞态、失败/取消释放、暂停续接；真实 RPC 形状使用受控进程验证。

协议依据同时核对官方 app-server 文档与本机 `codex-cli 0.145.0` 生成的类型；生成物只放在 Git 忽略的临时目录，不提交。自动化检查不冒充真实模型编码或 QQ smoke；真实外部任务需另行授权。
