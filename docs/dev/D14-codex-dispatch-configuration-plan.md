# D14：Codex Adapter 项目与派单配置

> 状态：实现、受控验收及两路独立复审完成（2026-09-30）。属于 `dev/v1.0-runtime-integration`；按可验证批次 commit，文档与代码分开提交，全部完成后统一 push，并由该分支创建一个 PR。不自动合并。

## 目标与确认边界

- 正式 Adapter 读取 `.huanlink/config/config.json` 显式引用的 runtime/project JSON，不再以遗留环境变量或硬编码分支选择执行目标。
- 派单必填稳定 `projectId`；`modelId`、`reasoningEffort` 可覆盖项目默认值。默认强度使用项目配置，仓库示例为 `high`；非法项目或模型/强度组合不启动 Codex 执行，不静默降级。
- 项目配置持有固定工作区和预期分支。工作区支持本机绝对路径或相对于 HuanLink 项目根的规范路径；模型不能传任意目录或分支。只验证，不创建 worktree、不切分支、不丢弃已有修改。
- 同一规范工作区同时最多一个活动 Task，忙时拒绝，不增加等待队列；不同工作区可并行。占位跨不同 Session 生效，`input-required` 仍占位到任务终态。
- 项目间 Codex 会话隔离；同一任务的追问保持原项目、模型和强度，不借 continuation 改配置。独立任务可重新覆盖执行参数。
- Core 只携带协议无关的结构化输入；Codex 参数校验、路径解析、分支保护、能力校验与会话隔离归 Adapter。A2A 集成负责结构化 Part 编解码，保留原派发未知/不自动重试语义。

## 分批实施

1. 配置与协议基础：项目默认强度、固定目录解析、Codex 模型能力列表和逐 turn 显式参数；公开测试先红后绿。
2. 派单闭环：Tool → Core → A2A → Adapter 结构化参数、项目会话隔离、工作区占位与续接冻结；正式 JSON 入口和配置 README。
3. 验收与审查：受影响包回归、类型/构建/格式检查、受控协议进程组合测试；两名独立只读压力 Reviewer，修复确认问题并复查后提交结果文档。

## 用户已确认的验收接缝

- 配置加载：默认值、合法/非法路径与分支、重复项目和实际工作区校验。
- MainAgent → A2A：必填项目、可选覆盖参数、准确结构化传递、来源去重、缺失/非法字段和现有 Task 生命周期不回退。
- Adapter → Codex：从 `model/list` 校验实际支持的模型和强度；不同项目 thread 不混用；同目录竞态、失败/取消释放、暂停续接；真实 RPC 形状使用受控进程验证。

协议依据同时核对[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)与本机 `codex-cli 0.145.0` 生成的类型；临时生成物已清理，可用 `codex app-server generate-ts` 重建，不纳入提交。自动化检查不冒充真实模型编码或 QQ smoke；真实外部任务需另行授权。

## 交付边界

- 配置与执行说明见 [本地配置 README](../../.huanlink/config/README.md)。默认值来自项目 JSON，覆盖不污染下一任务；非法组合不降级。忙时是受理前 RPC 拒绝，不是接受后再产生 rejected Task。
- 工作区与分支检查不阻止其他本机进程并发修改目录。线程隔离不是权限隔离；不同项目共用 app-server，启动结果不确定而关闭进程时可能影响其他活动任务。
- 关闭失败时保留停止未确认说明并拒绝新任务；不承诺已经发生的修改被撤销。Task 失败不是可安全重试的证明，仍需核对副作用。
- 旧 Adapter 执行环境变量不再生效，JSON 更改须重启 Adapter。仓库 `huanlink` 示例指向本仓库而非历史 smoke 目录；启动真实任务前需核对目标项目及分支。本次不自动启动/重启用户的服务。

## PR #9 后续修复：快照持久化失败（2026-10-04）

[Review P2](https://github.com/HuanHuanHuanFFF/HuanLink/pull/9#discussion_r4178266435) 指出：远端终态到达后，AgentCall 先更新内存，Task Store 写入失败；watcher 随后按内存终态退出，而持久 Task 仍未结束，配额与终态回流都被留住。已通过独立 Store 故障注入复现，不是实际填满生产 SQLite 磁盘。

- `11981e4`：区分 Store 读写异常与提交后的监听器异常。Store 失败时回滚临时 AgentCall 记录，防御性复制并保留已观察快照，只重试本地状态写入；提交后的监听器异常不回滚已提交事实，也不重放通知。
- 本地失败等待 1 秒再试；同一待写快照首次失败报告后台错误，持久化成功前保留名额，不伪造 `failed` 或触发完成回流。持续失败时，查询保持上次确认的 Task 状态，服务关闭可中断等待。
- `7642165`：让用户取消能打断续接快照的落库等待，随后走原有的一次远端取消；避免取消被本地 Store 故障无限阻塞。
- 本地写入重试自身不会重新派发、续跑、取消或重新查询远端。关闭及用户取消可以终止相应等待；仍不承诺跨重启保留尚未落库的快照、自动对账或恢复执行。

新增 6 项回归：瞬时读失败、瞬时写失败、持续失败及关闭、暂停回流后立即续接、提交后监听器抛错，以及取消与续接落库等待交错。瞬时故障用例还验证外部复用快照对象不会改变已保留的状态和 Artifact。
